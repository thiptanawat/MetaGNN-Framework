Data of the benchmark-validity studies of transcriptome-based metabolic reaction scoring on Recon3D: the curated colorectal cohort the studies run on, and the per-cell prediction arrays of the reaction-scoring audit. The code and the committed results are at {github}; this version of the record matches commit {commit} of that repository (Git tag {tag}).{revision_note} The cohort, and the audits of the scorer that led to this version, are described in the preprint https://doi.org/{preprint}.

Use this version. It replaces the cohort archive of the earlier versions of this record ({retired}; July 2026, also carried by the version of September 2026). That archive held a 220-patient colorectal set that was generated with a seeded random number generator and is not TCGA data, and reaction-feature tensors for the 624-patient cohort that were all zero because of a gene-identifier mapping failure. Both are reported in the preprint. In this version the 220-patient set is removed and the feature tensors are rebuilt; VERSION_NOTE.md inside the archive lists every change. The earlier versions remain accessible for the record and should not be used.

Files.

  • {cohort_name} ({cohort_size}, SHA-256 {cohort_sha256}). crc_624/: the curated TCGA-COAD/READ cohort of 624 primary tumors, one per patient, with the expression matrix, the GPR-mapped reaction features, the reconstruction-derived activity labels, the clinical annotation with microsatellite status, the stoichiometric, metabolite and edge files, and the fixed splits of the studies (crc_624/splits/splits.json). shared/: the Recon3D model file. brca/, luad/ and audit_extracts/: the breast and lung archives behind the label and input-invariance audits of the preprint. diagnostics/: the five checks of the preprint as scripts. SHA256SUMS.txt covers every file.
  • Ten tarballs of per-cell prediction arrays, one per result family, with their two checksum lists, unchanged from the version of September 2026. Unpack them into the directory results/prediction_arrays/ of the reaction-scoring audit in the repository and run that study's verify_ledger.py, which checks every array against the committed checksum list; the study's reproduction guide in docs/ gives the steps.
